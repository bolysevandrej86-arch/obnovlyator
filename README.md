# ⚡ Обновлятор

Приложение на Python, которое автоматически обновляет программы на Windows
через **winget** (и опционально pip-пакеты), чистит кэши и мусор, живёт в
трее и присылает уведомления — с красивым интерфейсом, разделением пакетов
на «**С VPN**» и «**Без VPN**» и защитой от ошибок.

## Запуск

**Вариант 1 — готовый .exe:** `dist\Obnovlyator.exe` (собирается скриптом
`build_exe.bat`, см. ниже). Python не нужен.

**Вариант 2 — из исходников:** двойной клик по **Обновлятор.bat** или
`python main.py`. Требуется Python 3.10+ и пакеты:

```bat
pip install customtkinter pystray winotify
```

(customtkinter — интерфейс; pystray + winotify — трей и уведомления,
необязательно: без них приложение работает, просто без сворачивания в трей.)

Самопроверка без интерфейса:

```bat
python main.py --selftest          # конфиг + winget + скан + VPN
python main.py --selftest --no-net # без обращения к сети
python main.py --smoke             # проверить, что UI собирается
```

## Как пользоваться

1. **«Проверить обновления»** — приложение сканирует winget и показывает
   карточки: имя, ID, текущая → новая версия, статус.
2. Разделы сверху: **Все / Без VPN / С VPN**, поиск, сортировка по имени.
   **F5** — обновить, **Ctrl+A** — выделить всё. Заголовок окна показывает
   состояние («4 обновл.», «обновление…») — видно на панели задач.
3. **Правый клик по пакету**: назначить VPN-категорию, **«Игнорировать эту
   версию»** (скрыть из списка до новой версии; скрытые — внизу списка,
   «Вернуть в список»), «ℹ О пакете» (сведения из winget show).
4. **«Обновить всё»** работает в два этапа: сначала обычные пакеты, затем —
   через VPN. Если VPN не активен и задана команда подключения, приложение
   само подключит VPN, дождётся его и обновит, а потом (по желанию) отключит.
5. Журнал внизу показывает всё, что делают установщики.

## Разделы

Навигация в сайдбаре: **📦 Обновления · 🧹 Очистка · 🗑 Мусор · 🕘 История**.

### 🧹 Очистка

- **Установщики winget** — инсталляторы, скачанные при обновлениях
  (папка `%TEMP%\WinGet`).
- **Временные файлы** — `%TEMP%`, только файлы старше суток, занятые
  пропускаются.
- **Кэш pip** — скачанные wheel-пакеты.
- **Кэш Центра обновления Windows** — `SoftwareDistribution\Download`
  (нужны права администратора).
- **Компоненты Windows (WinSxS)** — очистка через DISM, до получаса,
  только от администратора.
- **Кэши браузеров** — Chrome, Edge, Firefox (появляются, только если
  браузер установлен; при запущенном браузере очистка откладывается).

Внизу — **отчёты**: размер корзины (с кнопкой очистки) и файлы старше
30 дней в «Загрузках» (только показ, приложение их не удаляет).

### 🗑 Мусор (бесполезные программы)

Кнопка «Искать» запускает полную проверку по четырём секциям:

1. **Программы** — известный предустановленный мусор и триалы (Candy Crush,
   MSN-погода, «Начало работы», McAfee/Norton-триалы, магазинные соцсети…)
   со списком установленных из реестра. Удаление через winget, с подтверждением.
2. **Магазинные приложения (UWP)** — реклама из Microsoft Store, которой нет
   в «Программах»; удаление через `Remove-AppxPackage`.
3. **Задачи планировщика вне Microsoft** — OEM-аналитика и апдейтеры;
   отключение/включение (обратимо, через schtasks).
4. **Возможные остатки** — папки в Program Files/ProgramData, не совпадающие
   ни с одной установленной программой. Только Program Files: данные и
   сохранения из LOCALAPPDATA/APPDATA намеренно не трогаются. У каждой
   карточки — размер, «Открыть папку» и «Удалить» с подтверждением.

Ничего не удаляется само: всё — кандидаты, решение за вами.

### 🕘 История

Каждое обновление, очистка и удаление пишутся в `history.jsonl` — а раздел
показывает сводку «за 30 дней / за всё время»: сколько обновлено, сколько
ошибок, сколько места освобождено, сколько программ удалено.

Здесь же — **бэкап списка программ**: «💾 Сохранить список» (родной
`winget export` в JSON-файл) и «📥 Установить из бэкапа» (`winget import` —
после переустановки Windows вернёт весь софт одним файлом).

### Дополнительные источники пакетов

В настройках включаются: **pip** (Python-пакеты) и **npm** (глобальные
пакеты Node.js). Скрытые/ошибочные пакеты не обновляются автоматически.

## Трей и уведомления

При закрытии окно сворачивается в трей (иконка: «Открыть», «Проверить
обновления», «Обновить всё», «Выход») — по расписанию всё продолжает
работать в фоне. О находках и результатах приходят уведомления Windows.
Оба поведения отключаются в настройках. Если пакетов `pystray`/`winotify`
нет — приложение просто работает без трея (`pip install pystray winotify`).

## Права администратора

Если приложение запущено от обычного пользователя, в сайдбаре есть кнопка
**«🔑 Перезапустить от администратора»** (запрос UAC, текущий экземпляр
закрывается). От администратора обновления, очистка WinSxS и кэша
обновлений проходят без UAC на каждый пакет.

## Безопасность

- **Все установки идут через winget**, который сам проверяет SHA256-хэш
  каждого установщика по манифесту официального репозитория и пропускает
  его через SmartScreen. Приложение ничего не скачивает напрямую.
- Проверка VPN по IP принимает **только https**-URL; `http://` игнорируется.
- Команды подключения/отключения VPN выполняются как есть — их задаёте
  только вы в своих настройках.
- Второй экземпляр приложения не запускается (защита от гонки двух
  обновлений): ищите иконку в трее.
- Приложение никуда не отправляет данные: всё (конфиг, история, логи)
  хранится локально.

## Сборка в .exe

```bat
build_exe.bat
```

Получите `dist\Obnovlyator.exe` — один файл, Python на машине не нужен.
Рядом с exe хранятся `config.json` и `history.jsonl`, в подпапке `logs` —
журналы (пути те же, что у скриптового варианта; если папку exe нельзя
писать — используется `%LOCALAPPDATA%\Обновлятор`). Автозапуск и
«перезапуск от администратора» в exe-режиме ссылаются на сам exe.

Примечание: onefile-сборки иногда ловят ложные срабатывания антивирусов —
это норма для PyInstaller; при необходимости добавьте папку в исключения
или соберите `--onedir`.

## Проверки системы

Раздел «🩺 Проверки» — только диагностика, ничего не чинит и не удаляет:

- **Целостность Обновлятора** — сверяет файлы приложения с эталоном
  (записывается при первом запуске, обновляется после успешного
  самообновления). Мгновенно.
- **Драйверы: проблемные устройства** — устройства с ошибками, как в
  диспетчере устройств. Быстро.
- **Драйверы: обновления** — опрос Windows Update (1–5 минут); ставятся
  через сам Центр обновления.
- **Диски: SMART и место** — статус здоровья дисков и свободное место.
- **Система: хранилище компонентов (DISM)** и **целостность файлов (SFC
  /verifyonly)** — нужны права администратора; SFC долгая (5–15 минут) и
  только докладывает.
- **Диск: chkdsk /scan** — проверка файловой системного диска в режиме
  чтения (5–20 минут, от администратора).

## Настройка самообновления приложения

Механизм готов: релизы на GitHub Releases, манифест с sha256 и подписью
ed25519, докачка после обрыва, авт откат при двойном падении нового exe.
Одноразовая настройка:

1. Создайте публичный репозиторий, например `ivanov/obnovlyator`.
2. Впишите `owner/repo` в `selfupdate.py` → `SELFUPDATE_REPO`.
3. Публичный ключ уже вписан; приватный лежит в `release_keys/` — его
   никому не передавайте и не публикуйте (уже в .gitignore).
4. Публикация релиза: `python build_release.py --version 1.7 --repo
   ivanov/obnovlyator --notes "Что нового"` — скрипт соберёт exe, посчитает
   хеши, подпишет манифест и напечатает готовую команду `gh release create`.
5. Для команды `gh` нужна авторизация: `gh auth login` (CLI ставится
   через `winget install GitHub.cli`).

Пока `SELFUPDATE_REPO` пуст — приложение работает как раньше, проверки
пишут в журнал «отключено».

## Как определяется VPN

Достаточно любого признака (настраивается):

- среди процессов запущен VPN-клиент (WireGuard, OpenVPN, Amnezia, v2rayN,
  sing-box, Outline, NordVPN, ProtonVPN и т.д. — список редактируется);
- поднят сетевой адаптер, в имени которого есть WireGuard/OpenVPN/TUN/TAP/VPN…;
- по IP-проверке: если задан URL (**только https**, например
  `https://ipinfo.io/json`) и страна
  не совпадает с домашней (по умолчанию RU) — значит VPN работает.

Если VPN-пакеты не удалось обновить из-за отсутствия VPN — они помечаются
«пропуск», а не валятся с ошибкой.

## Настройки (окно ⚙ или config.json)

| Поле | Что делает |
|---|---|
| `vpn_processes` | подстроки имён процессов VPN-клиентов |
| `vpn_adapters` | подстроки имён сетевых адаптеров |
| `vpn_connect_cmd` | команда включения VPN (cmd), напр. `"C:\VPN\client.exe" /connect` |
| `vpn_disconnect_cmd` | команда выключения VPN |
| `vpn_disconnect_after` | отключать VPN, если приложение подключило его само |
| `vpn_home_country` / `vpn_ip_url` | проверка «не домой ли смотрит IP» |
| `timeout_sec` | таймаут на один пакет (по умолчанию 1800 с) |
| `retries` | повторные попытки после ошибки (1) |
| `winget_extra_args` | доп. аргументы, напр. `--scope user` |
| `update_pip` | обновлять также pip-пакеты |
| `update_npm` | обновлять также глобальные npm-пакеты |
| `auto_interval_hours` | автопроверка каждые N часов (0 — выключена) |
| `auto_update_all` | при автопроверке сразу обновлять всё найденное |
| `start_with_windows` | автозапуск приложения при входе в Windows |
| `theme_mode` | тема: `dark` / `light` / `system` (как в Windows) |
| `minimize_to_tray` | закрывать окно = свернуть в трей |
| `notify_enabled` | уведомления Windows о находках и результатах |
| `restore_point` | точка восстановления перед обновлением |
| `vpn_kill_switch` | прерывать загрузку VPN-пакета, если VPN отключился |
| `failed_updates` | пакеты с неудачной загрузкой: {ключ: версия} — не предлагаются, пока версия не сменится |
| `ignored_updates` | скрытые вручную («Игнорировать эту версию») |
| `categories` | какие пакеты обновляются через VPN |

Повреждённый `config.json` автоматически заменяется значениями по умолчанию
(битый файл сохраняется как `config.json.broken`, предыдущая версия —
`config.json.bak`).

## Защита от ошибок

- Все внешние процессы запускаются с таймаутами; зависший установщик убивается
  вместе с дочерними процессами, кнопка **«Остановить»** прерывает обновление.
- Каждая ошибка пакета — повторная попытка, затем карточка «ошибка» с
  **человеческим объяснением** (нет прав, источник вернул 404, таймаут сети,
  файл повреждён и т.п.), но обновление остальных продолжается.
- **Kill-switch VPN**: если VPN отключился во время загрузки VPN-пакета,
  загрузка немедленно прерывается, чтобы трафик не пошёл мимо VPN.
- **Точка восстановления** (по желанию, в настройках) создаётся перед
  «Обновить всё» — есть что откатить, если установщик что-то сломал.
- **Пакет, который не скачался, больше не предлагается**: снимается с выбора,
  получает метку «ошибка ранее» и пропускается при «Обновить всё» и
  автообновлении — чтобы не гонять заведомо падающие загрузки по кругу.
  Как только у пакета выйдет новая версия, он снова появится в предложениях.
  Вернуть вручную: правый клик по карточке → «Снова предлагать обновление».
- Ошибки движка никогда не роняют окно: UI получает только события из очереди.
- Весь журнал дублируется в `logs/obnovlyator.log` с ротацией по суткам.
- Если `winget` не установлен — приложение скажет об этом по-человечески.
- Без прав администратора работает: при необходимости Windows сам покажет UAC
  (в панели отображается предупреждение).
- Тема (`тёмная`/`светлая`/`как в системе`) запоминается и восстанавливается.

- **F5** — обновить текущий раздел (скан / размеры / поиск мусора / история).

## FAQ

Короткие ответы — и в самом приложении (раздел «❔ FAQ»).

- **Пакет помечен «ошибка ранее»** — загрузка не удалась; он не предлагается,
  пока не выйдет новая версия. Причина — в журнале с расшифровкой.
- **«Игнорировать эту версию»** — прячет пакет из списка до новой версии;
  вернуть: правый клик → «Вернуть в список».
- **VPN-категория** — правый клик по пакету → «Обновлять через VPN»; при
  обрыве VPN загрузка прерывается (kill-switch).
- **Права администратора** — можно без них (UAC появится сам); для тихих
  обновлений и очистки WinSxS лучше от админа (кнопка в сайдбаре).
- **Один экземпляр** — повторный запуск показывает окно уже работающего
  приложения (оно может быть свёрнуто в трей).
- **«Очистка» безопасна?** — да: установщики, временные файлы старше суток,
  кэши браузеров/pip, кэш установленных обновлений. Отчёты ничего не удаляют.
- **Файлы приложения** — config.json, history.jsonl, logs\ рядом с программой
  (у exe — рядом с exe); битый конфиг восстанавливается из .bak.
- **Самообновление** — работает после разовой настройки GitHub-репозитория и
  ключа подписи (инструкция в selfupdate.py).

## 🆕 Самообновление приложения (v1.5)

Обновлятор умеет обновлять **сам себя** через GitHub Releases — безопасно
и для вас, и для клиентов:

- проверка релизов в фоне (раз в N часов) + кнопка «Обновить сам Обновлятор»
  в трее + пункт в Настройках;
- канал обновлений: **stable / beta / nightly** (Настройки);
- скачивание с **докачкой после обрыва**, с проверкой **SHA-256** и
  **ed25519-подписи манифеста** (подделать обновление нельзя);
- замена exe без внешних утилит (Windows разрешает переименовать запущенный
  файл — на этом держится подмена), всегда с **бэкапом**;
- если новый exe упал при запуске 2 раза — **автоматический откат** на
  предыдущую версию + запись в Историю;
- обновление применяется только с вашего согласия («Обновить / Позже /
  Пропустить версию»), при выходе — тоже можно.

### ⚠ Что нужно сделать ПОЗЖЕ, чтобы самообновление заработало

Сейчас источник обновлений **намеренно не настроен** (плейсхолдеры в коде).
Когда будете готовы опубликовать релизы:

1. Создайте публичный репозиторий на GitHub, например `ivanov/obnovlyator`.
2. Откройте **`selfupdate.py`** и заполните вверху файла:
   - `SELFUPDATE_REPO = "ivanov/obnovlyator"` — сейчас пусто;
   - `SELFUPDATE_PUBLIC_KEY = "..."` — сейчас пусто (появится на шаге 3).
3. Один раз: `pip install pynacl` и `python build_release.py --make-keys-only`,
   затем вставьте напечатанный публичный ключ в `selfupdate.py`.
   **Папку `release_keys/` не публикуйте** — приватный ключ там.
4. Публикация релиза:
   `python build_release.py --version 1.6 --repo ivanov/obnovlyator --notes "Что нового"`
   — скрипт соберёт exe, посчитает хеши, подпишет манифест и напечатает
   готовую команду `gh release create`. После неё клиенты получат обновление
   автоматически.

До этих шагов всё приложение работает как раньше: проверки просто пишут в
журнал, что источник не настроен.

## 🆕 Прочее новое в v1.5

- **Экспорт истории** в txt/csv — кнопки в разделе «🕘 История» + график
  обновлений по дням за 14 дней.
- **Экспорт/импорт настроек** — Настройки → «Экспорт/импорт настроек»:
  перенос конфигурации на другой ПК одним файлом.
- **Правила пакетов** (Настройки → «Правила пакетов»):
  - *Чёрный список* — пакеты, которые никогда не обновлять;
  - *Закрепление версий* (`numpy=1.26.4`) — пакет держится на указанной версии;
  - *Минимум места на диске* — обновления не начинаются, если свободного
    места меньше указанного (ГБ).
- **Запрет сна** — Windows не уходит в спящий режим, пока идут обновления
  или очистка.
- Диалог обновления, история и настройки переживают смену темы —
  тема по-прежнему переключается «на месте».

### Новые поля config.json

Появляются автоматически со значениями по умолчанию:
`selfupdate_enabled`, `update_channel` (stable/beta/nightly),
`selfupdate_check_hours`, `selfupdate_skipped`, `blocked_packages`,
`pinned_packages`, `min_free_gb`.
